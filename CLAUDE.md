# CLAUDE.md — Public Site Production Orders

Read the repository-root `CLAUDE.md` first. This file adds the local rules for
work under `site/`. The public site is a projection of the vault, not a second
library. It renders; it does not invent.

Constitution: `Hermes/Memory/Public-Site.md`
Allowlist: `Hermes/Memory/Public-Publish-Allowlist.md`

## 1. What this folder is

Runnable HTML/CSS/JS for the free front door (The Verdict / Signs) and the
Library map (Menorah / Branch / entry reader). Live deploy is a separate
HTML-only repo. Redeploy with `bash Hermes/scripts/deploy_public_site.sh`.

Sod-level material and `SecretThings_*` never leave the vault by this
pipeline.

## 2. Local production orders

- **Allowlist before card.** No public entry card without a row marked
  `allowed` in `Public-Publish-Allowlist.md`. Default deny.
- Cards are summaries at public altitude. Do not paste full multi-lock
  writeups or Category-3 development.
- Physical claims keep the entry's stated limits (derived vs independent
  geometry, Newton-convention honesty, no sound-healing claims).
- When architecture or phase gates change, update `Hermes/Memory/Public-Site.md`.
  This folder's README stays run/routes-focused.
- One brand, three registers (`court` / `grace` / `library`). Do not invent
  a fourth accent or a second gold.
- CSS must be served over HTTP. `file://` is not a valid preview for layout.

## 3. Lessons learned

- **Public copy is not corpus voice.** Seeker-altitude pages collapse if they
  import GCHF vocabulary, S/T ratings, or sod. The Verdict stays forensic and
  general-revelation; the Library stays believer/student; neither dumps the
  locks.
- **Snowflake pairing is derived.** Public snowflake copy that implies the
  Menorah's independently specified bilateral pairing is a precision failure
  already named in Entry 2.1. State the boundary.
- **Deploy repo is HTML-only.** Vault-private Memory, Sessions, and corpus
  files must not be copied into the public source repo.

## 4. Maintaining this file — lessons learned, on explicit permission only

This file grows by lessons actually learned, not by anticipated advice.
At the conclusion of substantive work in this directory, propose a short
addendum: what was gotten wrong or sharpened, tied to that work, in the same
concrete style as §3. **Do not add it until the owner explicitly approves.**
Present the proposed addition, wait for a clear go-ahead, then write it in.
